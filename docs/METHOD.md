# 方法依据：有限总体无放回抽查的风险受控顺序审计

## 1. 问题与记号

- 整批 `N` 件（本工具约定 `N ≤ 120`），每件缺陷状态在抽查前**固定**，单一二元属性
  （`defect ∈ {0,1}`）。真实缺陷总数 `D ∈ {0,...,N}` 未知。
- **复合零假设** `H0: D ≥ d0`，`d0` 为 plan 的拒收阈值
  （`reject_if_defects_at_least`）。接受整批 = 拒绝 H0。
- **风险上限**：对**任意**满足 H0 的批次（任意 `D ≥ d0` 的缺陷配置），以及任意
  可依赖已揭示结果的查看/停止规则，"在任意查看时点曾被错误接受"的概率
  `≤ α`（plan 的 `max_false_accept_probability`）。
- 抽查顺序由 plan 冻结的算法对完整名单产生（`random.Random(seed).shuffle`
  作用于 Unicode 排序唯一件号），观察只能是该顺序的**连续前缀**
  `x_1..x_t`，`k_t = Σ x_i` 为累计缺陷数。未观察件不得当作合格。

## 2. 证据过程：混合似然比检验鞅

设计参数（**读取任何缺陷结果前冻结**，只依赖 plan）：

- 零假设边界 `d0`、风险上限 `α`、接受阈值 `1/α`；
- 备择混合权重 `w(d1)`：均匀分布在 `d1 ∈ {0,...,d0-1}`，各 `1/d0`；
- 查看批次 `batches`（只决定何时"看"，不改变任何前缀的证据值）。

第 `t` 抽后的证据定义为"混合备择 vs 边界零假设"的似然比。无放回简单随机
顺序下，含 `k` 个缺陷的**具体有序模式**在缺陷总数为 `D` 时的概率为
`C(N-t, D-k)/C(N, D)`，因此

```
M_t = Σ_{d1=0}^{d0-1} w(d1) · C(N-t, d1-k_t)·C(N, d0) / ( C(N, d1)·C(N-t, d0-k_t) )
```

接受规则：任一查看点 `M_t ≥ 1/α` 即接受整批并停止。

### 为什么有效（风险保证）

1. `M_0 = 1`，`M_t ≥ 0`。
2. 在边界零假设 `D = d0` 下，`M_t` 是**检验鞅**（test martingale）：
   它是同一零假设下备择混合与零假设的似然比，条件期望恒为 1
   （混合保持鞅性）。下述扩展规则在 `D=d0` 下以概率 0 触发，不影响鞅性。
3. 对任意 `D > d0`：给定历史，下一抽为缺陷的概率 `(D-k)/(N-t+1)` 关于 `D`
   单调不减；而 `M_t` 作为 `k_t` 的函数单调不增（超几何族对 `D` 有单调
   似然比，混合保持单调；扩展规则的 0 与 +∞ 分别位于值域两端，不破坏
   单调性）。两点分布上"随机更大 × 单调不增函数"给出
   `E_D[M_t | F_{t-1}] ≤ E_{d0}[M_t | F_{t-1}] = M_{t-1}`。
   故 `M_t` 在**每一个** `D ≥ d0` 下都是非负上鞅。
4. **Ville 不等式**：对非负上鞅，`P(∃t: M_t ≥ c) ≤ M_0/c`。
   取 `c = 1/α` 即得：对任意 `D ≥ d0` 的批次与任意停止规则，
   `P(曾在任意时点接受) ≤ α`。这正是题目要求的风险上限，且是
   **anytime-valid** 的：允许质检负责人随时追加查看、见好即停，
   也允许查看批次本身依赖已揭示结果。

### 为什么不用别的

- **反复算固定样本置信区间、遇有利即停**：固定样本区间只对预先固定的
  `t` 有效，反复查看会使真实覆盖率远低于名义值（可选停止问题）。
  本方法的 `M_t` 是检验鞅，Ville 不等式同时覆盖所有时点。
- **有放回近似（如二项/正态）**：无放回抽样的条件分布是超几何，
  用有放回近似后上述鞅性质不再成立，风险保证随之失效（除非另行证明
  某种界仍成立）。本方法全程使用**精确**超几何似然，不做近似，
  保证严格成立。

## 3. 似然项无法定义时的统计语义

混合似然比中组合数越界即取 0（对应"该缺陷总数下此观察不可能"）。两种
`0/0` 情形按统计语义处置，**不是数值掩盖**：

- `k_t > d0`：已观察到的缺陷数本身证明 `D ≥ k_t > d0-1`，即零假设
  **必然为真** ⇒ 证据 `M_t = 0`，此后永远不得接受（吸收态）。
- `d0 - k_t > N - t`：剩余未查件即使全部缺陷也凑不到 `d0`，零假设被
  **逻辑否证** ⇒ 证据 `M_t = +∞`，接受是无风险的逻辑结论
  （只可能在接近全量检查时出现）。

由此，全量检查到末件时 `M_N ∈ {0, +∞}`：合格批（`D < d0`）必接受、
不合格批必不接受，结论与真实缺陷总数一致（证书 `full_inspection` 块
显式记录该一致性）。

## 4. 数值实现

- 全部判定用**精确有理数**：`math.comb` 精确整数 + `fractions.Fraction`；
  `α` 由字符串精确解析（`"0.05"→1/20`、`"1/3"`）；浮点仅用于展示。
- 证据有两种独立实现：`evidence_value`（组合数形式）与
  `evidence_walk_product_form`（逐步条件概率比值的逐分量乘积）。
  `verify` 对每一前缀交叉核对两者一致；单元测试在 tiny 全部
  64 配置 × 720 排列 × 6 前缀上核对一致。
- 证据只依赖观察前缀 `(t, k_t)`：**更换查看批次不会改变同一前缀的证据**
  （`verify` 的 `batching_does_not_change_evidence` 检查用逐抽查看重跑
  并比对）。

## 5. 抽样资格（与统计证据分离的两段式）

统计结论只在抽样资格通过后才出具。资格检查（任一失败即整体失败）：

1. 名单件数 = `plan.lot_size` 且件号唯一（否则抽查算法本身无定义）；
2. 抽查顺序可按 plan 算法复现（记录其 SHA-256）；
3. 记录格式：`draw_no` 正整数、`defect ∈ {0,1}`；
4. `draw_no` 恰为 `1..m` 连续前缀（**漏序**/抽号重复在此暴露）；
5. 观察数 `m ≤ N`；
6. 件号全部在名单内（**未知件号**）；
7. 件号无重复（无放回，**重复件**在此阻断）；
8. 观察序列与 plan 顺序的前 `m` 位一致（**改序**/张冠李戴在此暴露，
   诊断给出应为/实为及该件在 plan 顺序中的位置）。

资格失败：`audit` 输出保留全部诊断的报告（`certificate_valid=false`，
不含统计结论），退出码 2，**不得继续出具有效审计证书**。

## 6. tiny 独立枚举验证

`fixtures/tiny.json`（`N=6, d0=2, α=1/3`）小到可以**独立**穷举：

- 全部零假设缺陷配置（`D ≥ 2` 的 57 个子集）× 全部 `6! = 720` 个抽查排列；
- 对每条路径用逐步条件乘积形式**逐前缀**重算证据，检查**整条路径上**
  是否曾达阈值（不只看末时点，不复用主算法的接受标记）；
- 每个配置下排列等权，`曾接受概率 = 曾接受排列数 / 720`。

结果：最大曾接受概率 `= 1/5 = 0.2 ≤ 1/3 = α`（在 `D=2` 的边界配置取得，
与手算 `C(4,3)/C(6,3)=1/5` 一致），风险上限成立；且全部合格配置
（`D < 2`）在任何顺序下全量检查末件前必被接受（一致性）。

## 7. 适用范围与限制

- 单一二元属性、`N ≤ 120`、顺序必须是 plan 算法产生的连续前缀；
- 混合权重是冻结的设计参数：更换权重只影响检验的效（多快接受合格批），
  不影响风险上限的有效性；
- 本工具只做离线审计与核验，不做抽样管理平台，也不做固定样本的
  效应量推断。
